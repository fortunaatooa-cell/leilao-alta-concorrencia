    3 · Desenho

    Arquitetura na AWS

    O caminho do lance tem uma única escrita. Tudo o que pode falhar sem invalidar o lance fica fora dele. A versão com os ícones oficiais da AWS abre no diagrams.net: abrir o desenho editável.

    1. Lance: o usuário envia o valor e uma Idempotency-Key; CloudFront e WAF filtram bots.
    2. Decisão: a Bid API no Fargate grava no DynamoDB só se a chave é nova e a versão do leilão não mudou.
    3. Evento: o commit sai no DynamoDB Streams, sem gravação dupla.
    4. Tempo real: a Lambda envia o novo preço a todos pelo WebSocket; se falhar, vai para a DLQ.
    4 · Explicação

    Como funciona, passo a passo

    O problema: race condition

    Ana e Beto leem o mesmo preço e mandam o mesmo valor. Sem proteção, os dois são aceitos.

    Ana lê preço = 100 Beto lê preço = 100 Ana grava 101 Beto grava 101 resultado: dois vencedores

    A solução: escrita condicional

    Grava só se ninguém mudou o leilão desde a leitura. Quem perde a corrida relê e é reavaliado.

    Ana grava (versão 0) OK → versão 1 Beto grava (versão 0) FALHA: versão mudou Beto relê: 101 não supera 101 + R$ 1 resultado: 201 para Ana, 409 para Beto

    Perguntas frequentes

    Por que não usar um lock?

    Um lock distribuído é mais um sistema que pode falhar, e o tempo dele pode expirar no meio da operação. Com a condição dentro do banco, conferir e gravar são a mesma operação atômica.

    Por que não ordenar pelo horário do celular?

    O relógio do cliente pode estar errado ou ser manipulado. Quem define a ordem é o servidor, no momento em que grava.

    E se o cliente não receber a resposta?

    Ele reenvia com a mesma chave e recebe a mesma decisão. Se usar a mesma chave com outro valor, recebe 422.

    E se um leilão receber 100 mil lances por segundo?

    Uma chave do DynamoDB aceita cerca de 1.000 escritas por segundo. A API recusa na hora quem está abaixo do preço atual, usando um cache, e só os lances plausíveis chegam à escrita condicional.

    E se a notificação falhar?

    O lance continua aceito. A notificação está fora do caminho do lance: falhas vão para uma fila de erros e o cliente pode consultar o preço a qualquer momento.
